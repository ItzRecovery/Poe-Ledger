Poe Ledger 0.38.1 — publishing and updates
1. Build and install this source release manually one last time. Close the prior application before building/installing.
2. Create a public GitHub repository you control (review source and licensing first). Upload the extracted source files, including the hidden .github/workflows/release.yml folder. Do not upload local saved data, Desktop, or build logs.
3. Run the Build Windows release workflow manually in Actions first. Inspect build logs and test the downloaded artifact installer on Windows. The manual workflow produces artifacts but does not publish a release.
4. After verification, create and push tag v0.38.1 (or the actual version in ProjectPoeLedger.csproj). The workflow builds and publishes the installer and release-manifest.json to GitHub Releases. Subsequent versions must update the csproj and Inno Setup version and output filename before tagging.
5. In Poe Ledger Help > Check for updates, enter https://github.com/OWNER/REPO/releases/latest/download/release-manifest.json and save the source. Replace OWNER and REPO with your actual repository.
6. Check for updates, then Download and install update when a newer version is offered. A verified download is followed by a SQLite snapshot backup in %LOCALAPPDATA%\ProjectPoeLedger\backups; installation uses the interactive Inno Setup installer. No SDK needed for self-contained releases. Backups do not include artwork/cache or browser profile; these stay in the existing data directory.
Security: Only use a repository you trust. SHA-256 verifies integrity against the manifest, not publisher identity. No code-signing certificate is included. Installer requires Windows and WebView2. Do not point to arbitrary release sources. No automatic startup checks or unattended installation.
